## Scope Rule

Treat a lesson as one bounded capability increment.

Treat a module as a short sequence that reaches one intermediate capability.

Treat a course as a dependency-aware path to an authentic terminal performance.

At module or course scope, map all lessons compactly. Expand only the lesson, module, or sample requested by the user.

Default to no more than 12 sequence rows and 1,500 words unless the user requests more detail. Cluster a larger source syllabus into capability families instead of creating one row or full contract per topic.

## Backward Capability Design

Start with the terminal performance, not a topic list.

Define:

- What the learner must produce or do in a new context.
- Which observable evidence counts as successful performance.
- Which constraints make the task authentic.
- Which knowledge and sub-capabilities are necessary for that performance.

Reject terminal goals such as "understand the field" unless they are translated into observable decisions, explanations, artifacts, or actions.

## Capability and Knowledge Map

Represent each required capability with:

- Stable identifier.
- Learner-visible description.
- Reason it supports the terminal performance.
- Prerequisite capabilities.
- Acceptance evidence.

Separate:

- Critical-path capabilities.
- Parallel capabilities that can be learned in either order.
- Optional enrichment.
- Capabilities assumed at entry.

Use a table for a small map. Use a dependency diagram only when relationships are difficult to read linearly.

## Sequence Design

Order increments so each module starts from a capability the learner has already demonstrated.

For every transition, state:

- Capability now available.
- New gap exposed by using it.
- Next increment that addresses the gap.
- Artifact or evidence carried forward.

Avoid artificial bottlenecks. A transition may also be motivated by increased complexity, a new context, a counterexample, a conflicting source, reduced scaffolding, or stricter performance conditions.

## Cumulative Practice and Feedback

Plan deliberate reuse of earlier capabilities.

Include:

- Retrieval or recall after a meaningful delay.
- A varied context rather than an identical repeated exercise.
- Feedback tied to observed failure modes.
- Scaffold fading from guided performance to independent performance.
- Repair and retry opportunities before terminal assessment.

Do not add spaced repetition mechanically when the course duration or learner goal does not support it.

## Assessment Architecture

Assign each assessment a role:

- Diagnostic: establish entry state or route around known material.
- Formative: reveal errors while support is still available.
- Cumulative: require earlier and current capabilities together.
- Terminal: test the authentic course outcome in a new context.

Check that assessment evidence samples the terminal capability rather than vocabulary recall alone.

## Pacing and Learner Variation

Estimate workload from learner actions, not reading length alone.

Identify:

- High-load concepts or transitions.
- Hidden prerequisite risks.
- Places where examples, partial solutions, or guided prompts are needed.
- Conditions for removing scaffolds.
- Optional acceleration and remediation paths.
- Accessibility, participation, tool, and format constraints.

## Terminal Transfer

Use a task that differs from the teaching examples while preserving the target structure.

Require the learner to select, adapt, justify, or combine capabilities rather than repeat a memorized procedure.

State what the course prepares the learner to do and what still requires later study, supervision, production validation, or domain experience.

## Compact-First Output

Return the smallest complete course map before expanding prose.

The default course deliverable contains only:

- Route, learner, assumptions, and terminal capability.
- Entry profile or diagnostic.
- Compact capability and prerequisite map.
- One sequence row per module or capability family.
- Cumulative practice and feedback rule.
- Assessment architecture and terminal transfer.
- Pacing and boundaries.

Apply the seven-part core contract internally to each module row. Do not print seven repeated subsections per lesson or topic unless explicitly requested.

When an output limit conflicts with detail, preserve full capability coverage, dependency order, acceptance evidence, and transfer assessment. Compress examples and prose first.

## Course-Level Audit Questions

- Does the terminal task represent the claimed outcome?
- Does every required module support a mapped terminal capability?
- Are prerequisites introduced before use?
- Does the sequence revisit earlier capabilities under new conditions?
- Is feedback available before high-stakes assessment?
- Does scaffolding fade?
- Is workload plausible for the target learner and duration?
- Can a learner transfer the capability beyond the course fixtures?
- Are stale sources, tools, datasets, or production assumptions identified for maintenance?
