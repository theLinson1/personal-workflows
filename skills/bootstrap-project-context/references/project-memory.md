# 持续项目记忆

来自本地 project-memory 的分类与历史复用方法。首次接入与后续维护使用同一事实来源，不强制创建四个文件或修改持久指令。

| 信息 | 值得保留的字段 | 何时使用 |
|---|---|---|
| 项目事实 | 配置/入口、来源、版本、验证状态、失效条件 | 实施前核对依赖和运行方式 |
| 决策 | 日期、问题、选择、替代方案、依据、接受的代价、替代旧决定的原因 | 调整架构或重新比较路线前 |
| 已知问题 | 症状、环境、根因证据、修复、验证、适用条件 | 相似问题出现时，先确认条件再套用 |
| 工作记录 | 当前状态、产物、未完成项、下一步 | 跨天或跨任务接续 |

小项目可先保留在一份 context；长到影响检索时再按类别拆分。使用项目已有目录、命名和负责人约定。入口文档只做短导航，详细记录按需读取。

新证据推翻旧事实时更新状态与时间；决策历史标记为“被某决定替代”，保留重审原因，不把互相矛盾的决定并列成同时生效。

仅记录非敏感配置和授权的访问方式。密码、API key、令牌不进入记忆文件；不把工作项目内容同步进个人方法仓库。必要时记录“从团队批准的凭据管理工具获取”，而非凭据值。

只在用户要求配置持久协作且现有约定允许时增补 `AGENTS.md` / `CLAUDE.md` 的简短导航，保留原有内容。建立 context 本身不意味着自动修改所有指令文件。
