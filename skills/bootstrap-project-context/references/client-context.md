# 客户端 context 观察点

按任务挑选相关内容。这是一份待调查清单，不包含目标公司的已知事实，也不指定技术方案。

## iOS 工程接手

- 工程入口：workspace/project、scheme、主要 targets、依赖管理、锁定版本、实际 CI 构建方式。
- 相关调用路径：UI 入口、业务逻辑、持久化、网络或硬件适配层。以文件和符号为依据，避免先贴架构标签。
- 生命周期与并发：资源归属、回调队列、异步任务取消、UI 更新边界；只关注当前问题涉及的部分。
- 已有测试与设备：能跑哪些测试、需要什么环境、哪些行为只能在真机上检验。

## 硬件交互

- 实际使用的传输方式、SDK 与硬件/固件版本，先看实现和文档。
- 连接、握手、命令、数据传输、断连与恢复各由哪一层负责。
- 日志是否足以关联一次操作，时间、设备和应用状态是否可比；保留在项目内部。
- 接口/协议资料是否完整，模拟数据与真机结果的边界在哪里。

不自行补全 UUID、帧结构、分片大小、错误码或重试语义。

## KMP 评估或接入

- 团队想通过共享解决哪个实际问题，以及已经确认的范围。
- 目前是否已有共享模块；哪些是事实、哪些仅是迁移设想。
- Kotlin、Gradle、Xcode 等版本与现有接入方式，依据项目配置确认。
- 平台能力、Swift 调用边界、异步与错误模型、资源生命周期和测试责任。
- 最小可验证的候选模块、行为对照方法与迁移期间的恢复路径。

共享业务逻辑与共享 UI 分别记录；“兼顾 KMP”不等于已经决定跨端 UI 改造。具体兼容性和 API 能力需在实施时依据项目版本查官方文档。

## 语音 / 云端链路（任务相关时）

- 从实际代码确认录音、上传、转写、摘要与结果展示的边界、状态和责任方；不要假定每一步都由本团队提供。
- 检查任务标识如何贯穿客户端、服务端和外部服务；中断、取消、重复提交、重试与部分成功怎样表达，以现有契约为准。
- 记录接口定义所在位置、可用测试环境和故障观测入口；原始录音、转写文本、用户数据与服务凭据保留在批准的工作环境。
- 将静态代码、测试替身、真实服务和真机结果分别标记，不能用其中一种证明整条链路完成。

这些是针对语音类任务的可选观察点，不代表目标项目的已确认实现。
