# 接入项目 context

个人方法说明怎样工作；context 说明当前项目的实际情况。项目 context 产生在项目里，不写回个人方法仓库。

## 从当前任务所需开始

先确认当前工作目录和相关仓库边界，阅读适用的 `AGENTS.md`、已有 context、README 与用户指定文档。优先补已有记录，避免建第二套相互冲突的说明。

读取当前模块已有的 ADR、已知问题与近期工作记录。遇到重复故障先比较原记录的症状、环境与适用版本；历史修复只在条件仍成立时复用。新方案与既有决定冲突时，说明哪些新证据改变了原来的取舍。

只为眼前工作收集必要入口：相关模块、构建与测试方式、关键行为和明确约束。需要更多背景时沿调用关系或文档链接扩展，不扫描整块磁盘、历史会话或无关凭据。

用户未提供仓库时，可以给出待采集模板与第一步，不要求提前知道全部架构，也不猜测公司内部信息。

## 记录来源和状态

对影响下一次任务的事实记录来源文件/命令、适用 commit 或版本（可获取时）、最近验证方式。区分已运行、静态读取、用户口述和未知。把会使记录失效的条件写清，例如构建配置或模块边界变更。

说明冲突证据：文档与代码不一致时不要静默合并；能运行就用实际行为辅助判断，不能运行则保留未知。用户转述可以成为带来源的信息，不冒充已验证代码事实。

## iOS / KMP 岗位的可选观察点

只有代码或任务相关时才读取 [客户端观察点](references/client-context.md)。岗位方向提示检查范围，不足以证明项目采用 SwiftUI、某个蓝牙协议或任何 KMP 层级。

缺少 Xcode、真机或公司依赖时仍可记录静态发现；把所需环境与下一条验证动作写清，不宣称已经构建或联调通过。

## 保存最小可维护结果

用项目现有文档位置；没有约定时可用 `docs/ai-context/context.md`，内容参考 [context 模板](assets/project-context.template.md)。只填当前有价值的字段，不为完整度制造内容。

后续持续维护时，按 [项目记忆规则](references/project-memory.md) 区分事实、决策、已知问题与工作进度；已有 `docs/project_notes/` 或 ADR 时直接更新那里，不并行创建另一套档案。

如果用户已要求建立 context，可直接生成项目文档。现有 `AGENTS.md` 只在有必要且处于请求范围时增补简短导航，不覆盖团队指令。不要自动提交或上传项目 context。后续任务只加载相关文件，按变化增量更新。
