# 定义问题

这是可试用的方法，不预设是用户已经确认的长期偏好。以当前请求、已有决定和项目证据为准。

## 先找会改变行动的信息

阅读已有任务材料和相关项目说明。确定要改善的结果、使用者、约束，以及怎样观察到成功。材料没有提供的事实保持未知；岗位名、技术名和常见实践只能提示查什么。

将用户已经选择的方向视为输入。只有发现具体矛盾时才说明代价并提出调整，不借澄清任务重新设计用户目标。

## 找到当前最值得解决的问题

- 区分表现出来的现象与需要改变的结果，追踪能支持因果判断的证据。
- 如果存在阻碍结果的约束冲突，说明冲突如何影响下一步；没有冲突时不必制造“唯一关键矛盾”。
- 选择能最大程度降低关键不确定性的下一步。必要时比较继续调查、做小验证和直接实现的成本。
- 缺少 context 时区分“现在必须知道”和“以后再补也不影响行动”。只询问前者，继续开展不依赖答案的工作。

## 按任务大小交付

简单问题用一个短段落；复杂任务可用下面的简表：

| 内容 | 结论 |
|---|---|
| 要实现的结果 | 可观察的变化 |
| 已知约束 | 依据与边界 |
| 完成证据 | 实际需要看到什么 |
| 当前关键未知 | 错了会影响哪项决定 |
| 下一步 | 最小动作、产物、验证方式 |

需要持续实施的任务继续推进。只有答案会实质改变方向、或必要输入确实缺失时提问，不设置固定的“用户确认关卡”。本 skill 本身不增加上传、发布或对外发送权限。
