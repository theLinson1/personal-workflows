# 隔离与基线

仅在隔离能减少分支冲突、并行写入或回退成本时采用。来自本地 using-git-worktrees；不是每次选型的固定步骤。

1. 确认仓库根目录、分支、未提交修改和当前是否已在独立 worktree。保留用户现有变更。
2. 优先使用项目的 worktree 位置约定；目录在仓库内时先检查 Git 忽略规则。新建的路径和起点必须明确。
3. 已有隔离环境就复用，普通可逆小改动直接在当前环境完成。
4. 按项目说明准备所需依赖，运行与本次工作相关的基线检查，记录原有失败。
5. 对比最终行为与基线，说明环境差异，不能把原有故障算作新回归。

创建隔离目录不自动包含合并、删除分支、删除 worktree 或推送。只执行用户请求涵盖的动作；为验证产生的临时目录可在确认只含本次临时产物后清理。
